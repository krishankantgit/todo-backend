# System Documentation: Architecture, Prompts & Data Model

This document covers the MongoDB data model and the AI prompts used during development, debugging, and deployment of the Todo application.

---

## 1. Data Model (MongoDB Schemas)

The application uses **MongoDB Atlas** with two primary collections: `users` and `tasks`.

### Relationship

```
users (1) ──────── (N) tasks
  _id   ←──────────  userId
```

- One user can own many tasks.
- Each task references its owner via `userId` → `users._id`.
- Task queries are scoped by `userId` (indexed) so a user only sees their own tasks.

---

### User Entity (`users` collection)

Stores authentication details and user profile information.

```json
{
  "_id": "ObjectId('65f1a2b3c4d5e6f7a8b9c0d1')",
  "name": "Krishan Kant",
  "email": "user@example.com",
  "password": "$2a$10$e8wV...hashedPasswordString"
}
```

| Field | Type | Rules |
|-------|------|--------|
| `_id` | ObjectId / String | Auto-generated by MongoDB |
| `name` | String | Non-blank (`@NotBlank` on register) |
| `email` | String | Unique index; validated with Jakarta `@Email` |
| `password` | String | Salted & hashed with `BCryptPasswordEncoder`; minimum 6 characters raw (`@Size(min = 6)`) |

**Validation (register DTO):**

- `name`: `@NotBlank`
- `email`: `@NotBlank` + `@Email`
- `password`: `@NotBlank` + `@Size(min = 6)`

---

### Task Entity (`tasks` collection)

Stores to-do items associated with an authenticated user.

```json
{
  "_id": "ObjectId('65f1a2b3c4d5e6f7a8b9c0d2')",
  "userId": "ObjectId('65f1a2b3c4d5e6f7a8b9c0d1')",
  "title": "Complete production deployment documentation",
  "description": "Prepare prompt ledger and MongoDB data schema doc",
  "completed": false,
  "createdAt": "2026-09-11T10:00:00.000Z"
}
```

| Field | Type | Rules |
|-------|------|--------|
| `_id` | ObjectId / String | Auto-generated by MongoDB |
| `userId` | String | Reference to `users._id`; **indexed** for per-user query performance |
| `title` | String | Mandatory |
| `description` | String | Optional text |
| `completed` | Boolean | Default `false` |
| `createdAt` | Instant (ISO Date) | Set on creation (`Instant.now()`) |

## 2. Prompts Used Across the Lifecycle

### Phase 1: Architecture & Backend Setup

- "Design a secure Spring Boot 3 REST API using MongoDB Atlas, JWT authentication, and stateless session management."

- "Write a Spring Security filter chain allowing CORS requests from a custom frontend domain while securing task endpoints with Bearer tokens."

- "Create DTO records for Register and Login requests with Jakarta Bean Validation for strict email matching and password constraints."

### Phase 2: Frontend Integration

- "Generate a clean, modern React authentication UI (Login/Register) using Vite and Tailwind CSS."

- "Set up an Axios interceptor to append JWT Bearer tokens to all outbound API requests and handle 401 redirect states."

### Phase 3: Cloud Deployment & Troubleshooting

- "Deploy Spring Boot 3 on Render with MongoDB Atlas connection string and dynamic port binding."

- "Deploy a Vite React SPA on Vercel and wire environment variables like `VITE_API_URL` into production builds."

- "Debug CORS errors and cold-start latency when connecting a Vercel frontend to a Render-hosted backend."

---

## 3. High-Level Architecture (brief)

| Layer | Stack |
|-------|--------|
| Backend | Spring Boot 3, Spring Security, JWT, Spring Data MongoDB |
| Database | MongoDB Atlas (`users`, `tasks`) |
| Frontend | React (Vite) + Tailwind CSS |
| Hosting | Backend → Render; Frontend → Vercel |

**Auth flow:** Register/Login → JWT issued → client stores token → Axios sends `Authorization: Bearer <token>` → secured task APIs.
